## Overview

Ajoute les 4 outils de test Go manquants (mockery, gofakeit/v7, testcontainers-go, testfixtures/v3) et harmonise les tests existants : `require` de testify partout, factories de données gofakeit seedées de façon reproductible, fixtures déclaratives YAML pour la suite d'intégration. `stretchr/testify v1.12.1` est déjà installé (`go.mod:15`) : rien à ajouter, seulement à généraliser. Dans ce document, « épinglé » signifie « version figée » (dans `go.mod` ou le Makefile, jamais de plage flottante).

## The Problem

État actuel vérifié dans le code :

*   `tests/article_test.go` est le **seul** fichier utilisant testify (`assert` importé ligne 27, mêlé à des `t.Fatal`) ; c'est aussi le seul à partager un état séquentiel via des variables de package (lignes ~120-144), documenté comme convention dans `AGENTS.md`.
*   Les cinq autres fichiers de test (`config/secrets_test.go`, `models/tenant_test.go`, `internal/db/pool_test.go`, `controllers/auth_test.go`, `middleware/auth_test.go`, `main_test.go`) n'utilisent ni `assert` ni testify : ils appelent directement `t.Fatal`/`t.Fatalf`/`t.Errorf` (déjà « fail-fast », mais sans unification).
*   Aucun mock (aucune interface générée), aucune factory, aucune fixture déclarative, aucune dépendance éphémère : chaque nouveau jeu de données se recopie à la main d'un test à l'autre, ce qui allonge chaque feature et fragilise le socle.

## Goals

*   Ajouter `github.com/brianvoe/gofakeit/v7`, `github.com/testcontainers/testcontainers-go`, `github.com/go-testfixtures/testfixtures/v3` au `go.mod`, et mockery (CLI, ligne v2) épinglé dans le Makefile selon le pattern `.cache/tools/` déjà utilisé (voir swag/sqlc/goose).
*   Configurer mockery sur les seules interfaces réellement mockables du projet : `DBTX` (`internal/db/db.go`) et `Querier` (`internal/db/querier.go`). Vérification faite : les packages `db` (Redis) et `models` ne déclarent aucune interface — ils sont hors périmètre.
*   Helpers dans `internal/testutil/` : factories gofakeit (Tenant, User, Admin, Article), chargeur de fixtures YAML, démarrage Postgres éphémère.
*   Harmoniser les tests existants : `require` partout (y compris conversion depuis `t.Fatal`/`t.Errorf`), fixtures YAML pour les données de départ de la suite d'intégration, factories pour les champs non déterminants.
*   Conserver `-race`, `-tags=all`, `-mod=readonly`, la connexion en rôles non-superuser, les skips Redis existants, et l'ordre d'exécution séquentiel documenté de `tests/article_test.go`.

## Non-Goals

*   Ajouter testify (déjà présent).
*   Couvrir les features du plan login (tests écrits par ce plan là-bas ; ils adoptent les conventions du présent plan si celui-ci s'exécute en premier).
*   Provisionner l'e2e Playwright (le plan principal utilise une base dédiée locale, hors de ce socle).
*   Rendre testcontainers obligatoire : Docker reste optionnel (skip propre) ; la suite `all` continue de tourner sur le PostgreSQL/Redis configurés.
*   Convertir `tests/article_test.go` à `testify/suite` dans la première passe (voir stratégie de retrofit — l'ordre alphabétique des méthodes de suite casserait l'ordre séquentiel documenté ; la conversion suite suit une phase dédiée, optionnelle et vérifiée).
*   Introduire des interfaces de store au-dessus de sqlc pour élargir la surface mockable (refactoring à valider séparément — voir Open Questions).

## Open Questions

*   Extraction d'interfaces de store (au-dessus du code sqlc généré) pour élargir la surface mockable : refactoring à valider séparément ; la 1re passe se limite donc aux interfaces existantes (`DBTX`, `Querier`).

## Critical User Journeys (CUJs)

### CUJ 1 : Checkout frais, suite verte avec le nouveau socle

*   **Given** : dépôt cloné, PostgreSQL + Redis actifs, `.env` présent, migrations appliquées.
*   **When** : `make test`.
*   **Then** : la suite `all` passe avec les fixtures YAML chargées via le pool admin et les factories seedées de façon reproductible ; l'ordre séquentiel de `tests/article_test.go` et ses scénarios RLS sont intacts ; les tests unitaires non tagués passent aussi sans services.

### CUJ 2 : Régénération des mocks idempotente

*   **Given** : le dépôt avec les mocks déjà générés et commités.
*   **When** : `make generate_mocks` puis relance immédiate.
*   **Then** : `git diff` vide après chaque relance (génération déterministe), mocks limités à `internal/mocks/` (interfaces `DBTX` et `Querier`).

### CUJ 3 : Sans Docker, tests isolés sautés proprement

*   **Given** : une machine sans daemon Docker.
*   **When** : lancement des tests testcontainers (opt-in).
*   **Then** : `t.Skip` avec la raison affichée au premier appel ; aucune erreur, aucun blocage ; la suite `all` ne dépend jamais de Docker.

## Technical Plan (Architecture)

*   **Dépendances** : ajoutées au `go.mod`, versions figées selon la procédure d'épinglage du plan détaillé (aucun choix laissé à l'implémenteur) ; aucune n'entre dans le binaire de production (usage `_test.go` + helpers uniquement).
*   **mockery** : CLI épinglé dans le Makefile (pattern `.cache/tools/`), config `.mockery.yaml` à la racine ciblant le package `internal/db` et ses deux interfaces ; mocks générés commités et vérifiés comme sqlc (relance → diff vide).
*   **testfixtures/v3** : fixtures YAML par table dans `tests/fixtures/` (`tenant`, `"user"`, `admin_user`, `article`) ; chargement exclusivement via le pool admin (rôle `app_admin BYPASSRLS`) — la RLS (Row-Level Security : filtrage PostgreSQL des lignes par tenant, `app.tenant_id`) empêche tout autre chemin d'insertion pour les tables isolées.
*   **gofakeit/v7** : factories dans `internal/testutil/factory.go` produisant structs et formulaires prêts à l'emploi, seedées par nom de test pour la reproductibilité.
*   **testcontainers-go** : démarrage d'un Postgres éphémère (opt-in, skip propre sans Docker) + migrations goose en bibliothèque, alignées sur la version du CLI du Makefile.
*   **Retrofit** : conversion `require` sur les six fichiers, fixtures YAML pour les données de départ de la suite d'intégration, factories pour les champs aléatoires ; l'architecture séquentielle de `tests/article_test.go` (variables de package) est conservée dans un premier temps.

```text
make test (inchangé) ─▶ go test -tags=all ─▶ suite all : fixtures YAML (pool admin) + factories gofakeit seedées
                                           └─ skips Redis si absent (convention conservée)
testcontainers (opt-in) ─▶ Postgres éphémère + goose lib ─▶ tests isolés (skip sans Docker)
make generate_mocks ─▶ mocks mockery commités (interfaces DBTX/Querier uniquement)
```

## Alternatives Considered

### Stack minimale (4 outils sans harmonisation des tests existants)

*   **Pros** : diff minimal, aucun risque de régression sur des tests verts.
*   **Cons** : les double conventions (`assert` + `testing` natif) persisteraient, et les nouveaux outils resteraient sans adoptants.
*   **Reason for Rejection**: Rejected by author — le retrofit unifie le socle ; le coût est borné par des conversions mécaniques (`t.Fatal` → `require`) vérifiées par la CI existante.

### gomock au lieu de mockery

*   **Pros** : gomock est l'outil officiel de l'écosystème Go.
*   **Cons** : mocks définis par du code ou des `//go:generate` dispersés (pas de configuration déclarative unique), moins de maintenance communautaire récente que mockery.
*   **Reason for Rejection**: Rejected by author — liste d'outils fournie : mockery retenu pour sa config déclarative unique (`.mockery.yaml`) et sa maintenance active.

### Fixtures en SQL brut (`.sql`) au lieu de testfixtures YAML

*   **Pros** : aucun chargement de dépendance, SQL exécuté tel quel.
*   **Cons** : pas de purge/chargement versionné par table, pas de références entre fichiers, duplication manuelle à chaque évolution de schéma.
*   **Reason for Rejection**: Rejected by author — testfixtures fournit le chargement déclaratif par table, réutilisable par la suite `all` et les futurs tests ; le SQL brut resterait à dupliquer manuellement.

--------------------------------------------------------------------------------

## Non-Functional Requirements

*   **Performance** : fixtures rechargées par suite (pas par sous-test) ; gofakeit seedé par nom de test (`gofakeit.Seed(int64(crc32.ChecksumIEEE([]byte(t.Name()))))`) pour reproduire tout échec.
*   **Compatibilité** : aucune modification du code applicatif hors `go.mod`/Makefile (les helpers vivent dans `internal/testutil`, package de test) ; CI inchangée hormis la vérification des mocks régénérés et le garde anti-fuite.
*   **Sécurité** : aucune clé réelle dans les fixtures ; mots de passe de test hachés bcrypt ; les tests restent en rôles non-superuser (`app_user`/`app_admin`).

## Detailed Implementation Plan

### Phase 0 — Dépendances et outils (repo stable : build + vet verts)

1.  `go.mod` / `go.sum` (Modify) —
    *   Procédure d'épinglage (aucun choix de version laissé à l'implémenteur) : `go get github.com/brianvoe/gofakeit/v7@latest`, `github.com/testcontainers/testcontainers-go@latest`, `github.com/go-testfixtures/testfixtures/v3@latest`, puis `go mod tidy` — la version la plus récente stable au jour de l'ajout est figée dans `go.mod` ; `pressly/goose/v3` est figé à **v3.20.0** (aligné sur `GOOSE_VERSION` du Makefile) ; vérifier avec `go mod verify`.
    *   Raison : socle de la suite de tests ; versions stables pour la reproductibilité des exécutions CI et locales.
2.  `Makefile` (Modify) — ajouter, sur le pattern exact des blocs swag/sqlc/goose :
    *   `MOCKERY_VERSION := <dernière version mineure de la ligne v2 au jour de l'ajout, figée>` ; `MOCKERY_BIN := $(CURDIR)/.cache/tools/mockery/$(MOCKERY_VERSION)/mockery` ;
    *   cible `install_mockery` : `@mkdir -p "$(dir $(MOCKERY_BIN))"` puis `@GOBIN="$(dir $(MOCKERY_BIN))" go install github.com/vektra/mockery/v2@$(MOCKERY_VERSION)` ;
    *   cible `generate_mocks: install_mockery` : `@"$(MOCKERY_BIN)" --config=.mockery.yaml` ;
    *   Raison : outils CLI épinglés et reproductibles, comme les outils existants du Makefile.

### Phase 1 — Configuration mockery et génération

3.  `.mockery.yaml` (Create) — contenu (adapter les clés au schéma de la version épinglée si des noms diffèrent — pas de choix de conception, vérification mécanique contre la doc mockery v2) :
    ```yaml
    with-expecter: true
    packages:
      github.com/Massad/gin-boilerplate/internal/db:
        config:
          dir: "{{.InterfaceDir}}/../../mocks"
          outpkg: mocks
          inpackage: false
        interfaces:
          DBTX: {}
          Querier: {}
    ```
    *   Raison : `DBTX` et `Querier` sont les seules interfaces du projet (packages `db` et `models` vérifiés : aucune interface — hors périmètre). Sortie dans `internal/mocks/` (commité, relance → diff vide).
4.  `internal/mocks/` (Create, via `make generate_mocks`) — mocks `DBTX` et `Querier` commités.

### Phase 2 — Helpers `internal/testutil`

5.  `internal/testutil/factory.go` (Create) — factories seedées (`gofakeit.Seed(int64(crc32.ChecksumIEEE([]byte(t.Name()))))` en tête de chaque factory) :
    *   `NewTenantFixture(t *testing.T) models.Tenant` — slug compatible `ValidSlug` (minuscules/tirets), nom d'entreprise gofakeit ;
    *   `NewUserFixture(t *testing.T) (models.User, forms.RegisterForm)` — email unique gofakeit, nom compatible validateur `fullName` (3-20 lettres), mot de passe 3-50 clair + hash bcrypt, entreprise gofakeit ;
    *   `NewAdminFixture(t *testing.T) (email, motDePasse string)` — email unique, mot de passe fort gofakeit ;
    *   `NewArticleFixture(t *testing.T, tenantID, userID uuid.UUID) forms.ArticleForm` — titre/contenu gofakeit.
    *   Raison : suppression des données inline ; reproductibilité par seed par nom de test.
6.  `internal/testutil/fixtures.go` (Create) — chargeur :
    *   `testfixtures.NewFiles(testfixtures.Dir("tests/fixtures"), testfixtures.Database("postgres"), testfixtures.Dialect("postgres"))` (API testfixtures v3) ;
    *   connexion via l'adaptateur `database/sql` de pgx (`github.com/jackc/pgx/v5/stdlib`) sur le DSN du pool admin — testfixtures exige `*sql.DB` ;
    *   `PurgeTables` : `TRUNCATE TABLE tenant, "user", admin_user, article CASCADE` sur le pool admin avant chargement ;
    *   `LoadFixtures(t *testing.T)` : purge + chargement, appelé une fois par suite (pas par sous-test).
    *   Raison : chargement déclaratif versionné par table, via le pool admin uniquement (BYPASSRLS — la RLS bloque toute insertion par `app_user` sans contexte `app.tenant_id`).
7.  `internal/testutil/postgres.go` (Create) — Postgres éphémère opt-in :
    *   image figée `postgres:16-alpine` ; démarrage via testcontainers-go avec attente de port ; migrations via `goose` en bibliothèque (pressly/goose/v3, `goose.Up` sur le DSN du conteneur, dir `db/migrations`) ;
    *   skip : l'échec de démarrage du conteneur (daemon Docker absent/injoignable) déclenche `t.Skipf("Docker indisponible : %v", err)` — la bibliothèque n'expose pas de fonction `IsDockerDaemonAvailable` ; la détection se fait par la gestion d'erreur du démarrage.
    *   Raison : tests isolés sans polluer l'instance locale ; optionnels sous Windows sans Docker.

### Phase 3 — Fixtures YAML

8.  `tests/fixtures/*.yml` (Create) — `tenant.yml`, `user.yml`, `admin_user.yml`, `article.yml` : reprendre **exactement** les enregistrements créés aujourd'hui en inline dans `tests/article_test.go` (identifiants, emails, mots de passe = hash bcrypt du mot de passe de test actuel, slugs, titres/contenus) — extraction mécanique, aucune valeur inventée. Clause conditionnelle : `admin_user.yml` n'inclut la colonne `name` que si la migration du plan login (`000003`) est appliquée sur la base ciblée.
    *   Raison : les données de départ de la suite `all` deviennent déclaratives et relisibles.

### Phase 4 — Retrofit des tests (chaque fichier : repo stable, `make test` vert)

9.  `tests/article_test.go` (Modify) —
    *   `assert` → `require` (import remplacé) ; `t.Fatal`/`t.Fatalf` → `require.NoError`/`require.Equal` équivalents ;
    *   données de départ en inline → `LoadFixtures` ; cas dynamiques → factories ; les tests RLS fail-closed existants (insert cross-tenant → `42501`, 0 ligne sans contexte — lignes ~658-711) sont préservés **verbatim** : ils sont les garants documentés de la RLS ;
    *   architecture conservée : variables de package, ordre séquentiel source, `TestIntDB` d'initialisation, `TestCleanUp` de nettoyage (convention `AGENTS.md`) — **pas de conversion suite dans cette passe** ;
    *   `assert` → `require` : conversions mécaniques uniquement.
10. `main_test.go` (Modify) — `t.Fatal`/`t.Fatalf` → `require.NoError`/`require.True` etc. ; email du superadmin de test et mots de passe remplacés par `NewAdminFixture(t)` (seed gofakeit) ; couverture du flag `-name` inchangée (plan login).
11. `config/secrets_test.go` (Modify) — `t.Fatal`/`t.Fatalf` (comparaisons attendu/obtenu dans les messages) → `require.Equal`/`require.ErrorContains` ; skips conservés.
12. `models/tenant_test.go` (Modify) — `t.Fatalf` → `require.Equal` avec arguments format ; sous-tests conservés.
13. `internal/db/pool_test.go` (Modify) — `t.Fatal` → `require.NoError` ; `t.Skip` (Redis/`trust`) conservés.
14. `controllers/auth_test.go` (Modify) — `t.Fatal`/`t.Error` → `require` ; données inline (emails/mots de passe de tokens) → factories.
15. `middleware/auth_test.go` (Modify) — `t.Fatal`/`t.Fatalf` → `require.NoError`/`require.Equal` ; UUIDs/emails inline → factories.
    *   Raison (9-15) : unification `require` et données reproductibles ; fichiers sans `assert` convertis depuis `t.Fatal` (mapping exact ci-dessus, aucune interprétation).

### Verification Plan

*   **Build & vet** : `go build -mod=readonly .` ; `go vet -mod=readonly ./...` ; `go mod verify`
*   **Mocks** : `make generate_mocks` deux fois de suite → `git diff` vide
*   **Unitaires** (tests non tagués, sans services) : `go test -mod=readonly -count=1 -race ./...` (le tag `all` exclut automatiquement l'intégration ; `invoice` requiert poppler) — couvre tous les paquets, y compris `internal/testutil`
*   **Intégration** : `make test` complet (PostgreSQL + Redis actifs) — suite `all` verte avec les mêmes garanties : ordre séquentiel de `tests/article_test.go`, tests RLS fail-closed intacts (l.~658-711), rôles non-superuser, skips Redis
*   **testcontainers (opt-in)** : avec Docker actif, les tests `internal/testutil` démarrent le conteneur et passent ; sans Docker, `t.Skip` propre avec raison affichée
*   **CI** : pipeline vert, y compris le nouveau garde « fuite helpers »

### Risks & garde-fous

*   **Ordre d'exécution de `tests/article_test.go`** : la conversion à `testify/suite` est écartée de cette itération — les méthodes de suite s'exécutent en ordre alphabétique (réflexion), ce qui casserait l'ordre séquentiel source actuel (`TestIntDB` en tête). Si une adoption suite est voulue plus tard : phase dédiée avec préfixes numérotés (`Test01_…`) et double exécution comparée avant bascule (1 re-audit maximum).
*   **RLS** : les fixtures passent exclusivement par le pool admin ; les tests RLS fail-closed existants (`42501` cross-tenant, 0 ligne sans contexte) sont les garants nommés et restent intacts — un insert `app_user` sans contexte doit continuer à renvoyer 0 ligne.
*   **Reproductibilité gofakeit** : seed obligatoire par nom de test dans chaque factory ; sans lui, un échec ne se reproduit pas.
*   **Fuite de dépendances de test** : garde CI dédié (n° 18) ; les deps ajoutées ne vivent que dans `go.mod` (`// indirect` interdits côté production) et `internal/testutil` n'est importé que par `*_test.go`.
*   **Alignement goose** : la bibliothèque `pressly/goose/v3` est figée à la même version que le CLI du Makefile (v3.20.0) pour éviter toute divergence de comportement des migrations.
