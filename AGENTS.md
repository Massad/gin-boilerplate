# AGENTS.md — go-artisan-services

API REST Go (Gin) avec PostgreSQL (pgx/v5 via pgxpool + requêtes sqlc, migrations goose), Redis (tokens JWT), Swagger et génération de PDF (maroto). Multi-tenant : schéma partagé + `tenant_id` + Row-Level Security échec fermé. Module : `github.com/Massad/gin-boilerplate`, Go 1.26.10.

## Commandes

- `make run` — lance l'app (`go run .`) ; le Makefile lit le même `.env` que l'app (`-include .env`) ; démarre d'abord la stack dev (prérequis `services_up`)
- `make test` — suite complète : recrée la base jetable `artisan_test` (`go run ./cmd/e2edb`, `E2E_DB_NAME=artisan_test`, `REDIS_DB=2` : DROP/CREATE + `FLUSHDB` de l'index 2) puis applique les migrations goose en superuser (superuser `postgres/postgres` épinglé : dev/CI uniquement — même convention que la recette `e2e` ; prod via `ALTER ROLE`), avant la commande de test existante `go test -mod=readonly -count=1 -p 1 -v -tags=all ./...` (prérequis `services_up` ; nécessite PostgreSQL + Redis actifs ; la cible source `.env` elle-même avant d'exécuter les outils, et masque sous Windows le `pdftotext` xpdf embarqué de Git for Windows : un poppler réel dans le PATH — `winget install --id oschwartz10612.Poppler` — est requis pour les tests PDF) ; aucune opération globale ne touche plus la base dev : les destructeurs des suites s'exécutent sur `artisan_test` (épinglée par le `TestMain` des paquets `tests`/`controllers`, `DB_NAME` posé au niveau processus, assertion `current_database()` à l'init) ; écritures résiduelles ciblées, non globales : la ligne `admin_user` de root `main_test.go` et les lignes `tenant` préfixées `pooltest-within-tx-` créées par les tests `WithinTx` d'`internal/platform/db/pool_test.go` (nettoyées par `t.Cleanup`) ; un `go test` direct hors make exige qu'un `make test` ait provisionné `artisan_test` une fois — échec explicite sinon, jamais de repli sur la base dev ; `make test` reste dépendant d'une première `make migrate_up` sur la base dev, à cause d'`internal/db/pool_test.go` (connexion réelle à la base configurée — lecture DSN, écritures `tenant` ciblées et nettoyées pour les tests `WithinTx`)
- `make e2e` — cycle e2e Playwright (prérequis `services_up`) : recrée la base jetable `artisan_e2e` (`go run ./cmd/e2edb`, drop/create en superuser épinglé `E2E_DB_ADMIN_USER/PASS`, `FLUSHDB` de l'index `REDIS_DB` (3 dans le cycle e2e) ; les sessions dev (index 1) ne sont plus purgées), migrations goose, fixture superadmin via le CLI (`-name "Prénom Nom"`) + owner tenant seedé par le projet `setup` Playwright (`POST /v1/user/register`), `pnpm build`, puis `pnpm exec playwright test` (webServer `go run .`, `DB_NAME=artisan_e2e`, `REDIS_DB=3`, port 9100, origine unique `app/dist`) ; prérequis PostgreSQL + Redis actifs, `.env`, et UNE fois `pnpm -C app exec playwright install chromium` — effet de bord attendu : le `FLUSHDB` purge l'index `REDIS_DB` (3 dans le cycle e2e), les sessions dev (index 1) subsistent
- `make services_up` / `make services_down` / `make postgres_up` / `make redis_up` / `make check_ports` — stack dev Docker (`docker-compose.yml` à la racine, projet `name: artisan-dev`, images `postgres:18-alpine` / `redis:8-alpine`, ports loopback `127.0.0.1:15432` / `127.0.0.1:16379`, volumes nommés, `--wait` sur les healthchecks) ; le prérequis `services_up` porte sur `run`/`test`/`e2e` uniquement — **jamais sur les migrations** (la CI les invoque aussi) ; `check_ports` échoue si compose et `.env` divergent sur les ports ; contrat du schéma : `services_up` démarre le cluster, `make migrate_up` (superuser) crée le schéma — démarrer les conteneurs ne dispense pas de la première migration ; reset destructeur : `docker compose down -v` (efface données et sessions Redis, re-login requis)
- `make migrate_up` / `make migrate_down` — migrations goose (`db/migrations/`, épinglé dans le Makefile). JAMAIS de `psql < db/*.sql` direct. Le superuser n'est requis que pour migrer (la migration 000002 crée les rôles `app_user`/`app_admin`) ; l'app et les tests se connectent en rôles non-superuser
- `make generate_sqlc` — régénère `internal/db/` ; à rejouer après TOUTE modification de `db/queries/` ou `db/migrations/`, code généré commité (la CI le vérifie par `git diff --exit-code internal/db`) ; sqlc épinglé v1.30.0 (v1.27.0 crashait au démarrage : runtime wasm wazero incompatible avec la toolchain Go locale) — outil encore flaky, relancer la cible en cas de panic
- `go run ./cmd/api -create-admin -email <e> -password <p> [-name "Prénom Nom"]` — bootstrap superadmin (CLI, aucune route HTTP) ; requiert le pool admin ; passe par le service admin (`admin.Service.Create`, ports nil — le CLI n'émet jamais de tokens) ; `-name` par défaut « Superadmin », upsert idempotent (email existant → mot de passe et nom remis à jour)
- `go test -mod=readonly -count=1 -race -v ./invoice` — tests PDF sans base de données (requiert `pdftotext` / poppler)
- `go build -mod=readonly .` et `go vet -mod=readonly ./...` — build + vet (toujours avec `-mod=readonly`)
- `make generate_docs` — régénère la doc Swagger (swag épinglé v1.16.6, installé via `make install_swag`)
- Frontend `app/` (pnpm épinglé par `packageManager` via corepack, Node ≥ 22.12 — pas d'installation globale de pnpm) : `pnpm storybook` (Storybook, port 6006), `pnpm build-storybook` (build statique), `pnpm lint` (config flat), `pnpm build` (`tsc --noEmit` + Vite), `pnpm test` (vitest : unitaires `app/src/**` — session/api/LoginPage ; les specs Playwright `app/e2e/*` sont exclues de l'include vitest) ; `storybook doctor` pour le triage ; les scripts de build npm exigent l'approbation `allowBuilds` dans `app/pnpm-workspace.yaml`
- CI (`.github/workflows/ci.yml`) : `go mod verify`, build, vet, vérif du code sqlc généré (`git diff --exit-code internal/db`), garde-fous « legacy drivers » (aucun import `sqlx`/`lib/pq`), tests avec `-race -tags=all`, smoke test des routes, `govulncheck ./...`. Migrations appliquées en superuser (`make migrate_up DB_USER=postgres DB_PASS=postgres`) + provisioning de la base jetable `artisan_test` pour les suites (2 lignes de l'étape « Configure disposable test services » : e2edb puis `make migrate_up DB_NAME=artisan_test DB_USER=postgres DB_PASS=postgres`) puis tests exécutés en `app_user`/`app_admin` non-superuser — la RLS est réellement prouvée. Job `frontend` indépendant (Node 22 + pnpm, `install --frozen-lockfile`, `pnpm lint`, `pnpm build`, `pnpm test`, `pnpm build-storybook` — Build → Test → Build Storybook) — pipeline Go inchangé

## Structure

- `cmd/api/main.go` — point d'entrée : dotenv, flags, secrets, deux pools pgx, Redis, puis `app.NewRouter` ; CLI `-create-admin` ; annotations Swagger principales (général info)
- `internal/app/router.go` — composition root : `app.NewRouter(deps)` — middleware chain (CORS/RequestID platform + gzip), routes `/v1`, Swagger non-prod, fallback SPA (`r.NoRoute`) ; partagé par `cmd/api` ET les suites (`tests/`)
- `internal/platform/config/` — validation des 3 secrets de signature (`ValidateSigningSecrets`)
- `internal/platform/redisdb/` — init Redis (`RedisDBIndex`, `InitRedis() error` (l'index vient de `REDIS_DB`)/`GetRedis`)
- `internal/platform/db/` — code GÉNÉRÉ sqlc (ne pas éditer à la main) + `pool.go` écrit à la main : deux pools pgx (tenant `app_user` / admin `app_admin BYPASSRLS`), `WithTenant` (RLS), `WithinTx` + interface étroite `InTx` (Unit of Work in-Tx — la `*Queries` liée au tx n'est atteinte qu'à l'intérieur du code exécutant, jamais en paramètre/retour d'un port cross-module ; `WithinTx` = wrapper strict de `Store.InTx`, aucun `set_config`), `postgresDSN`
- `internal/platform/middleware/` — CORS, RequestID (purs Gin) ; `internal/platform/validate/` — `DefaultValidator`, `Translate` (le validateur des routes, tag `binding:`)
- `internal/platform/httpx/` — répondants HTTP (`AbortMessage`/`JSONMessage`, forme `gin.H{"message": ...}`), mapping pgx→HTTP (`MapPgxError`), `ParseUUIDParam` (+ tests purs)
- `internal/modules/article/` — module pilote article : `handler.go` (routes `/v1/article*`), `service.go` (métier + port consommateur `ArticleRepository` + `ErrNotFound`), `repository.go` (requêtes sqlc via `pgdb.WithTenant` sur un `pgdb.Store` injecté au composition root), `dto.go` (form + messages), `model.go`, `service_test.go` (pur, fake du port)
- `internal/modules/auth/` — module auth (sessions/JWT) : `service.go` (`Service` + port consommateur `SessionRepository`, secrets injectés via `Secrets`), `repository.go` (sessions Redis : clés, index `user_sessions:*`, préfixe `admin:`, scripts Lua du soft-consume — client `*redis.Client` injecté au composition root), `middleware.go` (`TokenAuth(svc)`/`AdminAuth(svc)`/`RequirePermission`, politique RBAC), `handler.go` (UserLogout/AdminLogout), `model.go` (TokenDetails/AccessDetails/Admin*/Token/AdminToken/Secrets), tests : 7 middleware + ownership refresh + tests dédiés soft-consume (Redis index 2, `TestMain` pin `REDIS_DB=2` + `DB_NAME=artisan_test`) + suite pure (fake du port)
- `internal/modules/tenant/` — module tenant (slug + provisioning + données backoffice) : `service.go` (`Slugify`/`ValidSlug`, `ErrInvalidSlug`/`ErrSlugUnavailable`, boucle 99 tentatives `createTenantInTx`, `reservedSlugs` — racines de routes, commentaire pointé vers le contrat `TestAPISurface`), `repository.go` (`CreateInTx(ctx, pgdb.InTx, name)` / `List` / `UpdateStatusTx` sur un `pgdb.Store` pool admin injecté au composition root), `model.go` (`Tenant`, `AllTenantResponse`), `service_test.go` (pur, slugify/réservés) — module complètement migré : le port `TenantReader` (backoffice) est désormais déclaré par le module `admin` (Phase 6)
- `internal/modules/user/` — module user (identité) : `handler.go` (routes publiques `/v1/user/login` + `/v1/user/register`, byte-identiques), `service.go` (`Login` — status tenant vérifié **avant** bcrypt, `ErrTenantSuspended`→403, `pgx.ErrNoRows` préservé pour le fallback du login unifié ; `Register` — **un** `pgdb.WithinTx` : port `TenantProvisioner.CreateInTx` puis `CreateOwnerTx` sur le MÊME `pgdb.InTx`, « email already exists » via `ErrNoRows` sur l'insert ; `OneWithTenant`/`One` re-lectures ; ports consommateurs `TokenService` (impl `*auth.Service`) et `TenantProvisioner` (impl `tenant.Repository`) + vue UoW `TxRunner`(satisfaite par `pgdb.Store`)), `repository.go` (`ForLogin`/`GetUserWithTenant`/`CreateOwnerTx` sur pool admin injecté ; `One` via `WithTenant` pool tenant), `dto.go` (`LoginForm`/`RegisterForm` + messages), `model.go` (`User`, `TenantPayload` forme propre au module, `UserWithTenantStatus`, `UserLoginResponse`), `service_test.go` (pur, 12 tests) — implémente au câblage les formes des ports `UserAuthenticator`/`UserReader` (interfaces au collage Phase 7)
- `internal/modules/admin/` — module admin (backoffice plateforme) : `handler.go` (Login/Tenants/SetTenantStatus byte-identiques — casse `"Message"`/`"message"` recopiée ; l'émission des tokens admin passe par le port `TokenService` du module), `service.go` (`Login` vérification credentials bcrypt — **forme du port `AdminAuthenticator` `Login(email, password) (AdminIdentity, error)`, interface au collage Phase 7** ; `Create` upsert CLI ; `SetTenantStatus` — **un** `pgdb.WithinTx` : `TenantReader.UpdateStatusTx` PUIS `InsertAdminAuditTx` sur le MÊME `pgdb.InTx`, ordre épinglé par fake), `repository.go` (`GetAdminByEmail`/`CreateAdmin`/`InsertAdminAuditTx` sur pool admin BYPASSRLS injecté ; `tx.Queries()` confiné au repository), `dto.go` (`TenantStatusForm`/`AdminStatusMessages` + `LoginForm`/`LoginMessages` d'admin — tags et messages au byte depuis `user`), `model.go` (`AdminIdentity`), `service_test.go` (pur, 10 tests — ordre/unicité de Tx par fake, `tokens.issued == false` en login) — ports consommateurs `TokenService` (impl `*auth.Service`) et `TenantReader` (impl `tenant.Repository`, migré de `models/admin.go`, `pgdb.InTx` seul en signature)
- `internal/platform/mocks/` — mocks mockery commités (interfaces `DBTX`/`Querier`)
- `controllers/` — handlers HTTP restants (fenêtre transitoire A2) ; `auth.go` (login unifié + refresh, `*auth.Service` + `*user.Service` + `*admin.Service` injectés — le service admin alimente le fallback superadmin de `UnifiedLogin` et le service user la relecture `OneWithTenant` du refresh) ; les logouts user/admin ont migré dans `internal/modules/auth/handler.go`
- `models/` — structs DB et services métier restants ; `login.go` = login unifié (`UnifiedLogin(svc, users, admins, form)`, réponses discriminées par `kind`, bcrypt factice à coût constant + `DummyHashComparisons`) et porte `MessageResponse` (partagée par les annotations Swagger admin/auth/user — requalification au collage Phase 7) ; appellent le code sqlc via `pgdb.AdminStore()`
- `forms/` — formes restantes (fenêtre transitoire) : `auth.go` (`Token` du refresh) ; le validateur/`Translate` vit dans `internal/platform/validate/`
- CORS/RequestID sont dans `internal/platform/middleware/` ; les middlewares d'authentification (`TokenAuth(svc)/AdminAuth(svc)/RequirePermission`) vivent dans `internal/modules/auth/middleware.go`
- `db/migrations/` — migrations goose versionnées (000001 baseline uuid/timestamptz, 000002 multi-tenant : rôles, tables tenant/admin, RLS, grants, 000003 `admin_user.name` varchar NOT NULL DEFAULT 'Superadmin' — table plateforme sans RLS, back-compat)
- `db/queries/` — sources SQL de sqlc (articles, users, tenants, admins) : TOUTE requête SQL vit ici
- `cmd/e2edb/` — outil CLI d'infra des environnements jetables (drop/create de la base cible en superuser + purge de l'index `REDIS_DB` ; refuse l'index dev 1 quand `REDIS_DB` est absent), utilisé par le cycle e2e (`artisan_e2e`, index 3) et les suites Go (`artisan_test`, index 2 — chaque cible make épingle sa paire) ; garde-fous anti-DROP (nom vide / `DB_NAME` / `postgres` / `template*` refusés, identifiant quoté par pgx) + test unitaire pur
- `invoice/` — bibliothèque de génération de factures HTML/PDF, sans route HTTP
- `app/` — frontend Vite + React 19 + Tailwind 4 (TypeScript strict, pnpm) ; `app/.storybook/` — config Storybook (`@storybook/react-vite` 10, addons docs/a11y/themes, preview branché sur `app/src/index.css`) ; `app/src/design-system/` — palettes de tokens lues à l'exécution depuis les variables CSS de `app/src/index.css` (contrat jetons, pont « Open Design » futur) ; stories CSF colocalisées (`app/src/**/*.stories.tsx` + pages MDX) ; `app/e2e/` — specs Playwright (projet `setup` de seed + `chromium` des scénarios) ; `app/eslint.config.js` — lint flat couvrant `.storybook/` et les stories
- `docs/` — Swagger auto-généré (ne pas éditer à la main), `public/` — templates/statiques, `tests/` — tests d'intégration (tag `all`)

## Conventions

- Ajouter une ressource : requêtes dans `db/queries/*.sql` → `make generate_sqlc` → model dans `models/` (accès via `pgdb.TenantStore()`/`pgdb.AdminStore()`, métier tenant via `pgdb.WithTenant(ctx, tenantID, func(q *pgdb.Queries) error)`) → form dans `forms/` (tags `binding:` + map `XxxMessages`) → controller dans `controllers/` → route dans `internal/app` → `make generate_sqlc` (si requêtes) et `make generate_docs`
- Requêtes SQL uniquement dans `db/queries/*.sql` — aucune concaténation en Go (`fmt.Sprintf`, `+`), revu en review et refusé
- Pools : opérations « plateforme » (login, register, refresh, backoffice admin) → pool admin `pgdb.AdminStore()` (rôle `app_admin BYPASSRLS`) ; tout le métier tenant → pool `pgdb.TenantStore()` + `WithTenant` (contexte RLS réglé exclusivement par `set_config(..., true)` en transaction — jamais de `SET` session-wide sur un pool partagé)
- Login unifié (`POST /v1/login`, `AuthController.Login` → `models.UnifiedLogin(svc, users, admins, form)`) : tentative utilisateur tenant puis repli superadmin via le service admin (pool admin) ; réponse discriminée par `kind` (`tenant_user` avec user/tenant/token access+refresh, `superadmin` avec admin id/email/name/token access) ; erreurs 406 génériques à coût bcrypt constant (email inconnu → bcrypt contre un hash factice, pas d'énumération ni fuite temporelle) ; 403 propagé si tenant suspendu ; `/v1/user/login` et `/v1/admin/login` inchangés ; politique : un email superadmin ne recouvre jamais un email utilisateur tenant (utilisateur trouvé + mauvais mot de passe → 406, sans tentative admin)
- Multi-tenant : RLS échec fermé (`FORCE ROW LEVEL SECURITY`, policy `NULLIF(current_setting('app.tenant_id', true), '')::uuid`) ; le tenant vient UNIQUEMENT du claim JWT signé (jamais d'un header/hôte client) ; `tenant`/`admin_user`/`admin_audit` sans RLS (tables plateforme)
- Erreurs pgx : `pgx.ErrNoRows` → 404 ; `pgconn.PgError` par `Code` (`23505` unique → 406/409, `23503` FK → 409, `42501` RLS → 500) ; ne jamais renvoyer le texte SQL brut au client
- Erreurs de validation : toujours passer par `validate.Translate(err, forms.XxxMessages)` (`internal/platform/validate`) puis `c.AbortWithStatusJSON(status, gin.H{"message": ...})`
- Réponses JSON via `gin.H{"message": ...}` ; sessions JWT (Redis) gérées dans `internal/modules/auth` (`Service` + `repository.go`, soft-consume du refresh : record STRING `consumed:<1|0|recovered>:…`, grâce 5 min, échec fermé, sweep d'observabilité) avec index `user_sessions:*` et secrets injectés ; tokens admin préfixés `admin:`, signés avec `ADMIN_ACCESS_SECRET`
- 401 = non authentifié ; 403 = rôle insuffisant (`RequirePermission`) ou tenant suspendu
- Commentaires godoc sur les types/fonctions exportés ; pas de commentaires superflus dans le code
- Docs de librairies : pour chercher une information sur une librairie/framework, préférer l'appel au MCP `context7` (docs à jour) plutôt que d'explorer le code des packages — l'exploration de sources consomme beaucoup de tokens
- Décisions : quand les fonctions du skill `clef-decisions` peuvent rendre service à l'agent actif (choix d'action, routage/classification, jugement oui/non, scoring, questions groupées), le privilégier — ses compétences + son MCP `clef_decide` font économiser des tokens (probabilités calibrées en une passe, sans exploration ni long raisonnement)

## Tests

**Obligatoire : toute nouvelle feature doit être livrée avec ses tests, et les tests doivent être rejoués après chaque ajout/modification de code — le travail n'est pas terminé tant que `go vet` et la suite de tests passent.**

Trois niveaux :

- **Unitaires** (sans services, sans tag) : `internal/platform/config/secrets_test.go` (3 secrets ≥ 32 octets distincts), `internal/modules/tenant/service_test.go` (slugify/réservés, fonctions pures), `internal/modules/article/service_test.go` (pure, fake du port `ArticleRepository`), `internal/modules/auth/service_test.go` (pure, fake du port `SessionRepository` — claims, signaux soft-consume, admin), `internal/modules/user/service_test.go` (pure, fakes des ports — login/register/re-lectures : dup-email `ErrNoRows`, slug réservé/épuisé, 403 avant bcrypt, ordre provision→owner), `internal/modules/admin/service_test.go` (pure, fakes des ports — ordre `UpdateStatusTx`→`InsertAdminAudit` et unicité de Tx par fake, audit sauté si le statut échoue, `tokens.issued == false` en login), `internal/platform/httpx/httpx_test.go` (responders, MapPgxError, ParseUUIDParam), `invoice/invoice_test.go` (requiert `pdftotext` / poppler), `cmd/e2edb/main_test.go` (garde anti-DROP du tool e2e) — exécutables via `go test -mod=readonly -count=1 -race ./<pkg>`
- **Intégration** (derrière le tag `all`) : `tests/article_test.go` (suite HTTP complète via `httptest` + `app.NewRouter`, séquentielle : `TestIntDB` initialise, `TestCleanUp` nettoie, état partagé via variables de package ; isolation croisée, RLS fail-closed en SQL brut, rôles admin — `repository.go` article y est couvert), `internal/modules/auth/` (7 tests middleware + `TestRefreshOnlyConsumesMatchingOwner` + tests dédiés soft-consume : rejeu/grâce/recovery unique/fails-closed/sweep), `internal/platform/db/pool_test.go` (parse DSN pgx, mots de passe espacés/quotés ; `WithinTx` commit/rollback/jamais `SET` session-wide) — nécessitent PostgreSQL + Redis actifs (lancés via `make test`, qui source `.env` automatiquement)
- **E2E** (Playwright, hors tags Go) : `make e2e` — specs `app/e2e/*` (projet `setup` : seed de l'owner tenant ; `chromium` : scénarios) contre le binaire Go servant `app/dist` (origine unique, port 9100) ; base `artisan_e2e` jetable recréée à chaque cycle, `FLUSHDB` purge l'index `REDIS_DB` (3 dans le cycle e2e) — les sessions dev (index 1) ne sont plus purgées, effet de bord attendu

Conventions de test :

- testify (`require` partout), `httptest` + `gin.SetMode(gin.TestMode)`, `binding.Validator = new(forms.DefaultValidator)` pour les routes testées
- Outils de test Go (versions figées) : gofakeit/v7 (données seedées par nom de test), testfixtures/v3 (fixtures YAML `tests/fixtures/` chargées via le pool admin), testcontainers-go (Postgres éphémère opt-in, skip sans Docker), mockery (`make generate_mocks`, mocks commités dans `internal/mocks/` — interfaces DBTX/Querier)
- Helpers : `internal/testutil/factory.go` (factories), `fixtures.go` (chargeur), `postgres.go` (conteneur) — importés uniquement par des `*_test.go` (garde CI « fuite helpers »)
- La suite d'intégration `all` garde ses conventions : séquentialité, RLS prouvée, rôles non-superuser, skips Redis
- Secrets de test via `t.Setenv` (jamais de vraies clés), isolation via `t.Cleanup`, tests table-driven avec sous-tests quand pertinent
- Tests Redis : skip si `REDIS_HOST` absent ; répartition des index : 1 = sessions dev (défaut, `REDIS_DB` absent), 2 = suites Go, 3 = cycle e2e — toute création de client Redis dans un test passe par le `TestMain` du paquet (index 2 posé au niveau processus) ; les tests de parse de connexion exigent l'authentification `trust` PostgreSQL ; bases : les suites Go s'exécutent sur `artisan_test` (épinglée par le `TestMain` du paquet, `DB_NAME` posé au niveau processus) ; recréée+migrée par chaque `make test` ; le destructeur global de `TestCleanUp` est inoffensif sur une base jetable ; jamais `make test`, `make e2e` ou `go test` direct en parallèle dans le même checkout (Risques)
- Les tests se connectent en rôles non-superuser (`app_user`/`app_admin`) : une requête sans contexte tenant renvoie 0 ligne (RLS) et un insert cross-tenant lève 42501 — comportement attendu et testé, ne pas « corriger » en passant en superuser

Règles obligatoires :

- Nouvelle feature → écrire les tests en même temps que le code : cas unitaires sans dépendances quand possible + cas d'intégration dans la suite `all`
- Après chaque ajout/modification de code : `go vet -mod=readonly ./...`, puis les tests du/des package(s) touché(s), puis `make test` complet
- Ne jamais terminer un travail avec des tests en échec ou sautés par erreur ; si l'environnement manque (PostgreSQL/Redis indisponibles), le signaler explicitement

## Environnement & sécurité

- Copier `.env_rename_me` vers `.env` ; jamais commit `.env` ni de clés
- Dev local : dépendances en conteneurs Docker sur `127.0.0.1:15432` (PostgreSQL 18) et `127.0.0.1:16379` (Redis 8), compose `name: artisan-dev` (un seul projet quel que soit le clone) ; superuser `postgres/postgres` (conteneur dev uniquement), rôles applicatifs créés par la migration 000002 ; `SSL=FALSE` (API dev sur `http://localhost:9001`)
- `ACCESS_SECRET`, `REFRESH_SECRET` et `ADMIN_ACCESS_SECRET` : ≥ 32 octets, générés indépendamment (`openssl rand -hex 32`) et tous différents — l'app refuse de démarrer sinon
- `DB_USER`/`DB_PASS` : rôle applicatif `app_user` NON-superuser (RLS active) ; `DB_ADMIN_USER`/`DB_ADMIN_PASS` : rôle plateforme `app_admin` `BYPASSRLS` — les deux rôles sont créés par la migration 000002 elle-même ; mots de passe dev documentés dans la migration, la prod via `ALTER ROLE ...
