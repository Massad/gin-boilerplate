# Design system — introduction

Ce Storybook est le terrain d'essai du design system de `app/`. Il est ancré sur le
**contrat de jetons CSS** (`src/index.css`), pas sur des composants : les variables
oklch de `:root` et du bloc `.dark` sont la source de vérité partagée avec l'outil de
design externe (« Open Design »).

## Ce que vous y trouverez

- **Couleurs**, **Rayons**, **Typographie** : palettes lues à l'exécution via
  `getComputedStyle` — aucune valeur n'est codée en dur dans les stories.
- Le sélecteur de thème de la barre d'outils applique la classe `.dark` sur l'élément
  `<html>`, le même mécanisme que celui de l'application
  (`@custom-variant dark (&:is(.dark *))`) : ce que vous voyez basculer ici est ce que
  l'application exécutera.
- **Tokens** : la page de référence qui assemble toutes les palettes.

## Le pont à venir

Quand l'intégration « Open Design » réémettra les variables dans le même format que
`src/index.css`, ces pages et ces stories se mettront à jour sans restructuration :
aucun composant produit n'existe encore dans ce Storybook, et les palettes ne
dépendent que des variables.

## Conventions des stories

- Stories colocalisées : `src/**/*.stories.tsx`, format CSF, préfixe `_` pour les
  arguments inutilisés (compatibilité TypeScript strict).
- Chaque futur composant shadcn/Base UI doit embarquer sa story dès sa création.
- Le mode sombre se démontre via le sélecteur de thème, jamais via un état JS local.
